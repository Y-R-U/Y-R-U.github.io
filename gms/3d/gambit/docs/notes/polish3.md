## 1. "Illegal" king capture with only kings + a knight (battle-3 report)
**Cause**: not browser-specific and not a shim. `Chess.move()` started with `if (this.isGameOver()) return null`,
and `outcome()` reports `material` for a position that is *already* dead (K v K+N, K+B v K, …). `moves()` still
listed the moves, so a set-up FEN like `4k3/8/8/8/8/8/3n4/4K3 w` showed `Kxd2` as legal but `move('Kxd2')` was
refused (same in node: battle-3 probably checked `moves()` there). Adding a pawn made the position live.
Real games were never affected: they start from the initial position and end on the move that creates the dead
position (verified in the game screen, below).
**Fix** (`js/chess/chess.js`): `load()` records `_deadStart` (insufficient material at load); `move()` refuses via
`_ended()`, which ignores only the `material` end of a position that was loaded dead (and only without a manual
outcome). Everything else is unchanged: a capture that *creates* insufficient material still ends the game and
`move()` then returns null; mate/stalemate/50/threefold/resign/timeout still block.
**Tests**: `tools/core_perft.mjs` (+8 checks: dead set-up playable, K+N v K+P / K+N v K+B / K+N v K+Q / K+2N
after Kxd2 → material draw and further moves refused, resign still blocks, load resets the flag) — all pass.
Browser: gallery `BT.battle` with the dead FEN now plays (`Kxd2`, stomp 2.85 s); the live K+N v K+P case plays.
Game screen: a 120-ply resume (generated by `$SCRATCH/polish3/findline.mjs`) to `1n2k3/8/5r2/4K3/8/8/8/8 w`, real tap
`Kxf6` → sci-fi battle → "Draw by insufficient material", 0 errors. `puzzles_test` and `learn_test` still pass.
Note for learn: `js/learn/player.js` checks `isGameOver()` after a move, so a drill *starting* in a dead position
(K v K) would still say "draw" after the first move — none of the current drills do.
